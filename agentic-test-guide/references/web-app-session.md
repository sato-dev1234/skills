# Webアプリの起動条件・稼働確認・終了

## 起動方法と条件の確認

対象プロジェクトの文書、タスク定義、開発用スクリプト、設定、引数定義を読み、起動方法と、それに必要な条件を確認する。

- 実行する起動方法と作業ディレクトリ
- 起動または対象URLの確定に必要な入力
- 各入力が必須かどうか、既定値、利用可能な候補
- 対象URLの決定方法
- アプリが利用可能になったことを判定する方法
- 安全な終了方法が定義されている場合はその方法

値の名称や形式をスキル側で限定しない。単語が設定内に現れるだけでは必須入力とみなさず、起動方法または対象URLとの関係を根拠に判断する。

入力値は、次の条件で決める。

| 入力の状態と条件 | 行うこと |
|---|---|
| 利用者が値を明示しており、確認した起動方法と条件に矛盾しない | 再質問せず使う |
| 未指定だが、プロジェクトの唯一の候補または既定値で、起動方法・稼働確認・対象URLを一意に決められる | 根拠を添えて使う |
| 候補が複数ある、候補がない、または入力が任意か必須かを区別できない | 起動前に利用者へ確認する |

起動方法が複数ある場合は、対象、前提、結果の違いから一意に選べるときだけ選ぶ。一意に選べない場合は、コマンド文字列だけでなく選択に必要な違いを示して利用者へ確認する。

## 稼働確認

起動する前に、対象アプリが既に利用可能か確認する。稼働中なら再利用し、停止中の場合だけ確認した方法で起動する。

プロジェクトがhealth check、ポート、ログ、HTTP応答などの確認方法を定義している場合はそれを使う。定義がなければ、確定した対象URLへの到達を確認する。認証エラーなどHTTP応答があるだけでは対象画面を利用可能と判定できない場合があるため、プロジェクトの資料から期待する状態を判断する。

停止中のアプリを起動した場合は、利用可能になるまで無制限に待たない。プロジェクトの設定または起動方法から妥当な上限を決め、超過した場合はブラウザを起動しない。

## 終了できるプロセスの確認

利用者待ちや手動確認が終わり、アプリを残す必要がなくなった通常終了では、自分が起動した対象を確認済みの方法で終了する。終了できなかった対象は残件として報告する。

- 既に稼働していたアプリは、このスキルの終了対象に含めない。
- このスキルが起動したアプリは、起動方法、作業ディレクトリ、確認できるプロセス情報、安全な終了方法を控える。
- 終了を求められた場合も、このスキルが起動したことを確認できるプロセスだけを終了する。
- 子プロセスやプロセス群を安全に特定できない場合は強制終了せず、残っている状態とプロジェクトが定める終了方法を返す。
- アプリの起動後にブラウザ起動が失敗しても、このスキルが起動したことを確認できないアプリを推測で終了しない。維持したアプリと再開条件を返す。

インストール、データ初期化、環境の書き換えなど、通常の起動を越える準備が必要な場合は実行せず、必要な操作と再開条件を示す。

## 再開と終了に必要な情報

対象URL、起動方法と作業ディレクトリ、稼働確認の根拠、既存アプリか自分が起動したアプリかを控える。自分で起動した場合は、安全な終了に必要なプロセス情報も残す。利用者待ちや手動確認ではアプリを維持する。

停止時は、起動条件の確認中、稼働待ち、ブラウザ起動時など、止まった作業を示し、確認できた事実と再開条件を分ける。ブラウザの接続・終了情報は[接続の維持・終了](browser-session.md)に従って残す。
