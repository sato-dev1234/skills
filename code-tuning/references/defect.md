# 不具合検出の観点 (セキュリティ的不具合を含む)

変更したコードが、実行時に壊れる経路やセキュリティ的不具合を持たないかを見る。読み手は、共通の反復改善ルールを使う実行担当者と、この観点を担当する評価者。

## チェック項目

1. ヌル参照の危険、ヌル確認不足
2. エラー処理の不足、例外を握りつぶしている、エラー経路で誤った結果を返す
3. 境界条件のずれ (1 ずれ、空配列、空文字、上限・下限)
4. 競合、順序依存、再入問題
5. 資源 (ファイル、接続、ロック) の解放漏れ
6. 実行時例外を引き起こす可能性が高い処理 (型不整合、未定義参照、緩い等価比較)
7. セキュリティ的不具合: SQL / コマンド / コード注入、文字列連結による問い合わせ構築、利用者入力の無検証、認証情報のコード直書き、危険なデシリアライズ / 動的評価 (`eval` / `pickle` 等)

## この観点だけの判定規則

セキュリティ的不具合で重要度を上げる判断はコードチューニングの分類規則に従う。それ以外に、この観点だけで重要度を上げる規則は無い。

## この観点だけの自動修正可能性

セキュリティ的不具合の指摘で「パラメータ化問い合わせヘルパー」「サニタイザヘルパー」など修正に必要な共通処理を実コードベース内で確認できない場合は、修正案を提示するだけに留めて自動修正不能とする。実コードで確認できれば自動修正可能(共通化の観点で定めた、ヘルパーを実コードで確認できないときの境界規則をこの観点にも適用する)。

## 評価者へ渡す依頼

```

## 対象の差分
採用した差分全体を含める。

## この観点で見ること
1. ヌル参照の危険、ヌル確認不足
2. エラー処理の不足、例外を握りつぶしている、エラー経路で誤った結果を返す
3. 境界条件のずれ (1 ずれ、空配列、空文字、上限・下限)
4. 競合、順序依存、再入問題
5. 資源 (ファイル、接続、ロック) の解放漏れ
6. 実行時例外を引き起こす可能性が高い処理 (型不整合、未定義参照、緩い等価比較)
7. セキュリティ的不具合: SQL / コマンド / コード注入、文字列連結による問い合わせ構築、利用者入力の無検証、認証情報のコード直書き、危険なデシリアライズ / 動的評価 (eval / pickle 等)

## 制約
- セキュリティ修正に必要な共通処理 (パラメータ化問い合わせヘルパー、サニタイザヘルパー等) を実コードベース内で確認できなければ、修正案のみ提示し自動修正不能として返す
- 読み取り専用。コードは修正しない

## 指摘の返し方
各指摘について次を添える:
- 対象ファイルと行
- 指摘の要約と内容
- 重要度 (critical / high / medium のいずれか。判断に迷えば書かなくてよい。最終判定は呼び出し側が決める)
- 修正可能性候補 (自動修正可能 / 自動修正不能。判断に迷えば書かなくてよい)
- 根拠 (行番号と該当コード片 1-3 行。行番号だけは不可)
- 修正案
```
