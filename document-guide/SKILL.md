# ドキュメント作成ガイド

文書の構成と固定欄を決め、整理された本文を組み込む。本文の意味と、表・列挙・段落・図の関係を、見栄えの都合で変えない。

## 構成を決める

読み手、目的、依頼範囲、既存成果物を確認する。文書の役割は、利用者の指定、会話や概要の案内・リンク、資料の表題と内容から確かめる。名前や更新時刻だけで対象を決めず、候補を区別できない場合は利用者へ確認する。

[構成一覧](references/composition-selection.md)で、役割、読み手、目的に合う構成と見本を選ぶ。該当する見本がなければ、依頼と本文の話題に合う構成にする。構成は話題、固定欄、必要な図を決めるために使う。各項目を表や段落にする判断には使い直さない。

## 出力先を決める

保存先は、利用者の指定または既存成果物の配置に合わせる。どちらからも一つに決められない場合は利用者へ確認する。

| 対象・出力先の状態 | ファイル名・形式・保存の扱い |
|---|---|
| 利用者がファイル名を指定している | 指定に従う。ファイル名の拡張子と指定された形式が食い違う場合は確認する |
| ファイル名の指定がなく、対象の既存資料を確認できた | 既存の名前と形式を維持して更新する |
| ファイル名・形式の指定も対象の既存資料もない | 構成一覧の既定名と形式を使う。該当する見本がない場合は、文書の役割に合う名前と形式を決める |
| 対象の既存資料がなく、形式だけが指定されている | 指定された形式に合わせて構成一覧の既定名の拡張子を変える |
| 予定出力先に別用途のファイルがある | 上書きせず、別の出力先を決める |

見本の名前を理由に既存資料を改名したり、同じ役割の資料を重複作成したりしない。

## 本文を文書へ組み込む

選んだ見本を読み、本文と根拠に合わせて題材、固定欄、図、確認状況を置き換える。本文や必要な情報が不足している場合は、その不足を明らかにし、推測で完成させない。

HTMLの場合は[HTMLへの組み込み](references/html.md)に従う。Markdownの場合も、確定した見出し・表・列挙・手順と条件の適用範囲を保ち、HTMLタグを混在させない。

見本内のリンクは例として扱い、成果物の実際の参照先へ差し替える。

見本の「書き手へ:」という注記は固定欄と見た目の扱いを示す。成果物へは写さない。本文と見本の固定欄が競合する場合は、意味を変えて埋めず、相違点を示す。

既存文書は依頼された対象と範囲だけ更新する。上書きが依頼に含まれるか判断できない場合は、別ファイルに完成案を保存し、対象を確認する。

## 保存して完成を確認する

保存した文書を開き、本文と固定欄の対応、表示、必要な切替操作を確認する。実装中、レビュー前、未実施、判定不能などの状態を、見本の完成例で置き換えない。

対象範囲、選んだ構成、保存先、重要な未確認事項を報告する。表示や操作を確認できなかった場合は、未確認として残す。
