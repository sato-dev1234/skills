# HTMLへの組み込み

本文で確定した見出し・表・列挙・手順・図の関係を、次の配置へ写す。[共通CSS](../templates/common.css)と選んだ見本を読み、同じスタイルを使う。

## 画面の構造

| 本文の構造 | HTMLでの配置 |
|---|---|
| 第1階層の節 | ナビゲーションとパネル |
| それ以降の節 | パネル内の見出し |
| 対応 | 表 |
| 列挙 | 箇条書き |
| 手順 | 番号付きリスト |
| 共通の主体・条件・場面 | 表やリストの導入 |
| 個別の条件や理由 | 対象のセル・項目 |
| 読み手の前提 | 通常の本文には出さず、パネルやナビゲーションの数にも含めない。レビューの根拠に必要な場合だけ示す |

説明する単位が1件なら、`detail-page-layout--single` の1カラムにし、ナビゲーションと切替スクリプトを置かない。段落、表、リスト、図を、見栄えの都合で別の形式へ変えない。

## 見本の内容を置き換える

見本の表示部分は完成形の例である。「書き手へ:」という注記は、その部分の役割と保つ固定欄を示す。

| 注記の有無 | 内容の決め方 |
|---|---|
| ある | 固定欄と置き換える内容を注記で確認する |
| ない | 表示部分の役割を読み取り、題材の内容へ置き換える |

見本を使う際は、次を守る。

- 題材、ファイル、確認内容、指摘、状態を、対象の根拠に基づいて置き換える。
- 「書き手へ:」の注記を成果物に写さない。
- 図表の読み方、印の意味、書き方の約束は本文に説明せず、必要な対応を見出し、図の題、凡例で示す。
- 注記と本文の構造が競合したら、一方を自由に選ばず、競合を示す。

## ファイルの作り方と確認

HTML1ファイルで表示と操作が完結するように作成する。

- 共通CSS、見本固有CSSの順で `style` に埋め込む。
- 必要なJavaScriptと画像を埋め込む。
- 外部フォントは引き継がず、端末のフォントを使う。

組み込みを終えたら保存して開き、表示、切替操作、組み込む前の本文との対応を確かめる。

既存ファイルの更新は、次の範囲で行う。

| 依頼の状態 | 保存の扱い |
|---|---|
| 上書きする対象が指定されている | 依頼された対象だけを上書きする |
| 上書きが依頼に含まれるか判断できない | 別ファイルに完成案を保存し、対象を確認する |
