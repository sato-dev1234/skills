注文のキャンセル期限 — 既存テストのレビュー

レビュー観点

キャンセル期限のテストについて、呼び出すコードと検証式を確認する。実装の誤りを検出できるか、実行順や処理時間で結果が変わらないかを評価する。

観点確認内容今回の確認対象
検証内容仕様どおりに動かないとき、テストが失敗するかキャンセルを拒否したときの応答とDBの内容を、テストがどう確かめているか
独立性テストを実行する順や、ほかのテストが残したデータ・設定で結果が変わらないか一覧で使うキャンセル可能日数を、どのテストで設定し、いつ元に戻すか
安定性正しく実装したのに、処理時間や実行環境が違うことでテストが失敗しないか注文を用意してからサーバーが判定するまでに、期限切れになることがないか

現在のテストで見つけられる不具合

server/test/orders/OrderCancelService.test.ts — 既存テスト

it('期限切れを拒否し、何も保存しない', async () => {

  expect(response.status).toBe(422);
  expect(response.body.reason).toBe('cancel_window_exceeded');

サーバーの動作現在のテスト理由
DBを変更せず、期限切れを理由に422を返す成功するstatusとreasonが期待値に一致する
期限が切れた注文のキャンセルを受け付け、200を返す失敗するstatusが異なるため、誤りを検出できる
422を返すが、理由が期限切れではない失敗するreasonが異なるため、誤りを検出できる
注文をcanceledに更新した後、期限切れを理由に422を返す成功してしまう応答は一致し、テストが保存結果を比較していない

書き手は、表の結果を掲載した検証式から判断しており、実行して確かめていない。最後の行は、注文を更新してから拒否する不具合があった場合の例である。

要求の前後でDBの内容を比べる

テストは、応答を確かめる処理を残し、キャンセルの要求前後でDBの内容が変わっていないことも確認する。テストは、応答が正しくても注文を更新してしまう不具合を、DBの内容の比較で見つけられる。

期間内のキャンセルを受け付ける

テストは、キャンセル可能日数が3日の契約先について、期限内ならキャンセルを受け付けることを確かめる。対象の注文は、出荷前・決済済みである。サーバーは、仕様では期限に達した時点からキャンセルを拒否する。

server/test/orders/CancelWindow.integration.test.ts — 既存テスト

it('期限内の要求を受け付ける', async () => {
  const placedAt = new Date(Date.now() - 3 * DAY_MS + 100);
  const order = await seedPaidOrder({ placedAt });
  const response = await client.cancel(order.id);
  expect(response.status).toBe(200);
});

準備から判定までにかかる時間

テストは、注文の保存後に要求を送り、応答後に検証するために await を使う。ただし、待機中にも時間は進むため、判定時には期限切れになる可能性がある。

以下は、テストの Date.now() とサーバーの now() が同じ時刻を基準にし、保存した注文日時のミリ秒精度が保たれる場合の予測である。時計の設定と保存時の精度は未確認である。

準備開始から判定まで仕様上の結果200を期待する現在のテスト
40ms期限より前なので200成功する
100ms期限ちょうどなので422正しい実装でも失敗する
250ms期限を過ぎたので422正しい実装でも失敗する

表は、所要時間ごとの予測であり、遅延を加えた実行結果ではない。

判定に使う時刻を固定する

テストは、Serviceが期限の判定に使う時刻を固定すれば、処理に時間がかかっても期限内として同じ結果を得られる。期限までの余裕は、増やすだけでは、処理が遅れたときに結果が変わることを防げない。

server/test/orders/CancelWindow.integration.test.ts — 改善案

it('期限内の要求を受け付ける', async () => {
  const fixedNow = Date.parse('2026-04-04T09:59:00Z');
  const app = await createTestApp({
    clock: { now: () => fixedNow },
    cancelWindowDays: 3
  });
  try {
    const order = await app.seedPaidOrder({
      placedAt: new Date('2026-04-01T10:00:00Z')
    });
    const response = await app.client.cancel(order.id);
    expect(response.status).toBe(200);
  } finally {
    await app.close();
  }
});

テストが clock.now で固定するのは、期限を判定するときの時刻だけである。テストは、注文の保存が終わるまで待つ処理と、応答を待つ処理には、引き続き await を使う。finally に置いた app.close() は、テストが失敗したときも呼ばれる。

  2. 改善案を適用する。
  3. 処理を意図的に遅らせてもテストが成功することを確認する。
