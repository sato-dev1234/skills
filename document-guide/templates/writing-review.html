注文キャンセルの画面表示と受付

条件別の答えと、受付を断った後の扱いを分けて読む。

対象と規則

対象は、注文キャンセルの要件メモから抜き出した9文です。元のメモ全体ではありません。位置は元のメモの段落と文を示し、句読点を含めた原文を各話題に掲げます。原文の主張を共通要素でまとめ、できた親の子も整理してから文章へ写します。

結果

  • 注文詳細画面では、注文の条件ごとにキャンセルボタンと案内の表示を対応させました。原文にない案内の扱いは補っていません。
  • キャンセル要求では、「注文の条件→キャンセルできるか」を一つの対応にし、受付を断った後の注文と操作履歴の扱いを別の枝に置きました。
  • 画面表示や端末時刻に頼らない理由と、返金処理を変更しない範囲を保ちました。

話題と原文の対応

話題原文位置内容

言葉の修正

読み手には、注文、出荷、設定変更とキャンセル要求を理解していることを前提とします。サーバーの判定は、その場で何を判断するかが分かる言葉にします。

共通要素から親と子を整理する

次は、原文の共通要素から親を作り、その子も整理した途中の枝です。注文詳細画面では注文の条件ごとの表示を、キャンセル要求では注文の条件ごとの可否をそれぞれまとめます。受け付けなかった後の扱いは、可否とは別の枝に置きます。

注文キャンセルの画面表示と受付
├─ 注文詳細画面の表示
│  └─ 注文の条件 → キャンセルボタンと案内の表示
│     ├─ 期限超過 → ボタンを表示せず、案内を表示する @1-4
│     └─ 出荷済み → ボタンを表示しない @2-6
└─ キャンセル要求の受付
   ├─ 注文の条件 → キャンセル可否
   │  ├─ 期間未設定の契約先の出荷前 → キャンセルできる @2-4
   │  ├─ 出荷済み → 受け付けない @3-2
   │  └─ 期限超過 → 受け付けない @3-2
   └─ 受け付けなかった要求の扱い
      ├─ 注文を変更しない @3-4
      └─ 操作履歴へ記録しない @3-4

表示と可否は、それぞれ条件別の結果を比較する枝です。受け付けなかった後の扱いは可否の表の行には入れません。残る主張も次の一本のツリーで位置付けます。

二つの「対応」はそれぞれ画面表示とキャンセル可否を扱います。拒否後に何をしないかという指示は、可否と別の枝です。条件が重なる場合も各条件を適用し、原文にない優先順位は加えません。

書き直した文章

キャンセル要求の受付

サーバーは、キャンセル要求を受け付けるとき、最新の設定でキャンセルできるか判断します。画面の表示状態や利用者の端末時刻にかかわらず、誤ったキャンセルを防ぐためです。

原文にある条件別の扱いは次のとおりです。期間が未設定の契約先について従来どおりの扱いを保つのは、既存の契約先の操作に予告のない制限を加えないためです。

注文の条件キャンセル可否
期間が未設定の契約先の出荷前の注文従来どおり、いつでもキャンセルできる
出荷済みの注文受け付けない
期間を過ぎた注文受け付けない

受け付けなかった場合は、注文を変更せず、操作履歴にも記録しません。

期間の導入に伴う返金処理は変更しません。
