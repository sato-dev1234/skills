# コード調査

依頼の問いには、確認できた事実だけを根拠に答える。返すのは依頼された調査結果に限り、実装、修正、成果物の保存、依頼にない提案へ広げない。

## 調べ方

1. 依頼と会話から、問い、対象、制約、比較元、調査の手がかりとして既に分かっている情報を確認する。答えが変わる情報が足りなければ、推測せず確認を求める。
2. 広く読む前に `git status --short` を確認する。未コミット変更は、依頼が対象に含める場合だけ調査対象へ加え、その他の変更と混同しない。
3. 最初に調べる箇所は、依頼での明示の有無に応じて選ぶ。

   | 依頼での明示 | 最初に調べる箇所 |
   |---|---|
   | ファイル、エラー、API、コマンドの明示がある | 明示されたもの |
   | 明示がない | 問いに直結する履歴、公開APIやCLIなどの処理を呼び出す箇所、テストの順で優先して選ぶ |

4. ブランチやPRの変更を調べる場合は、比較元を次の優先順で決める：明示された比較元、現在ブランチの追跡ブランチ、リポジトリで一意に確認できる既定ブランチ。分岐点、分岐後コミット、`比較元...HEAD` の差分を確認する。未コミット変更を含める場合は `git diff HEAD` も読む。
5. 最初に調べた箇所から、呼び出し先、状態、入出力、処理が失敗した場合の流れを、問いに必要な範囲だけ辿る。検索では、既読コードにある識別子やエラーで範囲を絞り、一致箇所の前後を読む。

## 調査の根拠

- テストの名前や記述、コミットメッセージ、検索結果、ファイル名や識別子名、文書は、対象コードや差分を読むまで挙動の根拠にしない。
- 読んでいない範囲、実行していない確認、外部サービスの挙動は未確認として分ける。
- テストの実行結果は、実行して確認できた範囲の事実として扱う。対象コードや差分と照合せずに挙動全体を断定しない。

## 調査結果と未確認事項を返す

問いへの答えを先に示す。確認した事実、事実から直接導ける判断、未確認事項を区別し、根拠にしたファイル、差分、履歴、実行結果を分かるように書く。

問いを特定できない場合、最初に調べる箇所を決められない場合、比較元を一意に決められない場合、または権限・外部サービス・手動再現が必要な場合は、試した範囲と必要な情報を示して調査を止める。
