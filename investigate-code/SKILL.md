# コード調査

依頼の問いへ、確認できた事実だけを根拠に答える。依頼された調査結果だけを返し、実装、修正、成果物の保存や依頼にない提案へ広げない。

## 調べ方

1. 依頼と会話から、問い、対象、制約、比較元、調査の手がかりとして既に分かっている情報を確認する。答えが変わる情報が足りなければ、推測せず確認を求める。
2. 広く読む前に`git status --short`を確認する。未コミット変更は、依頼が対象に含める場合だけ調査対象へ加え、それ以外の変更と混同しない。
3. 明示されたファイル、エラー、API、コマンドを最初に調べる箇所にする。明示がなければ、問いに直結する履歴、公開APIやCLIなどの処理を呼び出す箇所、テストの順で選ぶ。
4. ブランチやPRの変更を調べる場合は、明示された比較元、現在ブランチの追跡ブランチ、リポジトリで一意に確認できる既定ブランチの順で比較元を決める。分岐点、分岐後コミット、`比較元...HEAD`の差分を確認し、未コミット変更を含める場合は`git diff HEAD`も読む。
5. 最初に調べた箇所から、呼び出し先、状態、入出力、処理が失敗した場合の流れを問いに必要な範囲だけ辿る。検索は既読コードにある識別子やエラーを使って範囲を絞り、一致箇所の前後を読む。

テスト、コミットメッセージ、検索結果、名前、文書は、対象コードや差分を読むまで挙動の根拠にしない。読んでいない範囲、実行していない確認、外部サービスの挙動は未確認として分ける。

## 調査結果と未確認事項を返す

問いへの答えを先に示す。確認した事実、事実から直接導ける判断、未確認事項を区別し、根拠にしたファイル、差分、履歴、実行結果が分かるように書く。

問いを特定できない、最初に調べる箇所を決められない、比較元を一意に決められない、権限・外部サービス・手動再現が必要な場合は、試した範囲と必要な情報を示して止める。
