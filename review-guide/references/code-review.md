# コードの確認

次の観点で、変更後のコードと関連する既存処理を調べる。

## 確認観点

- 共通化: 同じ役割の既存処理と入力・結果・利用条件を比べ、再利用できるか。
- 保守性: 役割分担、分岐、状態管理から、仕様変更の影響範囲を追えるか。
- 効率: 処理回数や取得・保持するデータ量が必要以上に増えていないか。
- 不具合: 境界値、拒否、例外のとき、応答と保存結果が仕様どおりか。

## 調べ方

1. 依頼と確認済み要件・設計から、今回の実装に期待する動作と確認範囲を特定する。
2. 変更後のコードと関連する既存処理について、呼び出し先・データの流れ・確認結果を調べる。差分だけで判断できない箇所は、確認できた範囲と未確認の範囲を分ける。
