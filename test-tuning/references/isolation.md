# 独立性の観点

変更したテストが、共有状態や実行順に依存せず単独で成立するかを見る。読み手は、共通の反復改善ルールを使う実行担当者と、この観点を担当する評価者。

## チェック項目

1. 共有された可変状態 (`process.env`、`argv`、大域変数、モジュールレベルの `let` / `var`)
2. 実行順依存 (`beforeEach` / `afterEach` 不足、状態を保護していない)
3. 後始末不足 (`afterEach` / `afterAll` で状態が片付かない)
4. テスト同士の依存 (あるテストが別のテストの実行を前提に書かれている)

## この観点だけの判定規則

次は critical に格上げする:

- モジュールレベルの可変共有状態で実行順依存が起こる
- テスト同士の依存 (順序前提でしか動かない)

後始末不足、`beforeEach` / `afterEach` 不足は high。

## この観点だけの自動修正可能性

- 「`process.env` を一時的に上書きしてリストアする」修正のように、テストファイル内で閉じる場合は自動修正可能とする。本体 API 変更が必要なら自動修正不能とする
- モジュールレベルの可変共有状態 (`let cache = []` 等) のリセット修正は次で判定する:
  - テストファイル内で `beforeEach(() => { cache.length = 0 })` のようなテストファイル内変数の直接初期化で完結するなら自動修正可能とする。ただしリセットを入れると同ファイル内の別の検証式 (その共有状態の累積値を期待している `expect`) が破綻する場合は、リセットだけで閉じない。破綻する検証式を直すのはテストの意図変更にあたるため自動修正不能側に倒し、修正案のみ記録する
  - 本体側の状態 (本体モジュールが内部に持つキャッシュ等) を `clearCache()` のような本体公開関数で初期化する必要があり、その関数が実コードで確認できないなら自動修正不能とする(修正案のみ記録)
  - 初期推定: テストファイル冒頭で `let X` が宣言され、`X.push` / `X.pop` などの更新もテストファイル内にあるなら、その変数はテストの下準備データとみなして自動修正可能扱いにする。本体モジュールから読み込んでいる場合や、宣言箇所がテストファイル外にあるなら本体公開関数が必要として自動修正不能側に倒す

```
あなたはテストコード差分を独立性の観点で評価する読み取り専用の評価者です。修正はしません。

## 対象の差分
採用した差分全体を含める。

## この観点で見ること
1. 共有された可変状態 (process.env、argv、大域変数、モジュールレベルの let / var)
2. 実行順依存 (beforeEach / afterEach 不足、状態を保護していない)
3. 後始末不足 (afterEach / afterAll で状態が片付かない)
4. テスト同士の依存 (あるテストが別のテストの実行を前提に書かれている)

## 制約
- モジュールレベルの可変共有状態による実行順依存、テスト同士の依存は critical で返す
- テストファイル内で閉じるリセット修正は自動修正可能、本体 API 変更が要るものは自動修正不能として返す
- 読み取り専用。テストコードは修正しない

## 指摘の返し方
各指摘について次を添える:
- 対象ファイルと行
- 指摘の要約と内容
- 重要度 (critical / high / medium のいずれか。判断に迷えば書かなくてよい。最終判定は呼び出し側が決める)
- 修正可能性候補 (自動修正可能 / 自動修正不能。判断に迷えば書かなくてよい)
- 根拠 (行番号と該当コード片 1-3 行。行番号だけは不可)
- 修正案
```
