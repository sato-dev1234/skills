# 安定性の観点

変更したテストが、時間・順序・非決定的データ・環境差で壊れないかを見る。読み手は、共通の反復改善ルールを使う実行担当者と、この観点を担当する評価者。

## チェック項目

1. 時間待ち頼み (固定 `sleep`、固定タイムアウト)
2. 順序前提 (繰り返し処理の順、Map/Set 列挙順、非同期完了順を前提)
3. 非決定的データ依存 (現在時刻、乱数、外部サービス、システム時計に直接依存)
4. 固定値依存 (環境依存パス、ポート、ホスト名、利用者ホームディレクトリ)

## この観点だけの判定規則

時間待ち / 非決定的データ / 固定値依存 (環境差で確実に壊れる) は critical。

固定値依存の判定補助:

- 「ホームディレクトリ依存」(`/home/...` / `~/...` / `process.env.HOME` 等を含む固定パス) は常に critical 扱いとする。CI / 別利用者 / Windows 環境で確実に壊れるため

## この観点だけの自動修正可能性

この観点だけの例外は無い。テストチューニングの自動修正不能条件に従う(テストファイル内で閉じる修正は自動修正可能、本体 API 変更が要るものは自動修正不能)。

```
あなたはテストコード差分を安定性の観点で評価する読み取り専用の評価者です。修正はしません。

## 対象の差分
採用した差分全体を含める。

## この観点で見ること
1. 時間待ち頼み (固定 sleep、固定タイムアウト)
2. 順序前提 (繰り返し処理の順、Map/Set 列挙順、非同期完了順を前提)
3. 非決定的データ依存 (現在時刻、乱数、外部サービス、システム時計に直接依存)
4. 固定値依存 (環境依存パス、ポート、ホスト名、利用者ホームディレクトリ)

## 制約
- 時間待ち / 非決定的データ / 固定値依存は critical で返す。ホームディレクトリ依存は常に critical
- 読み取り専用。テストコードは修正しない

## 指摘の返し方
各指摘について次を添える:
- 対象ファイルと行
- 指摘の要約と内容
- 重要度 (critical / high / medium のいずれか。判断に迷えば書かなくてよい。最終判定は呼び出し側が決める)
- 修正可能性候補 (自動修正可能 / 自動修正不能。判断に迷えば書かなくてよい)
- 根拠 (行番号と該当コード片 1-3 行。行番号だけは不可)
- 修正案
```
