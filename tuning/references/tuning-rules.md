# 共通の反復改善ルール

このルールは、対象を固定し、現在の担当者とは別の評価者に読ませる、または実行させて、指摘を修正しながら再評価する手順を定める。評価観点、判定項目、修正範囲、完了条件、出力規則は、利用者の指示または使用側 skill の規則から評価前に固定する。

## 適用範囲

| このルールが扱うこと | 使用側の規則が扱うこと |
|---|---|
| 評価者を起動する共通条件 | 評価観点 |
| 評価者へ渡す依頼に必ず含める条件 | 判定項目 |
| 評価結果の整理 | 評価者へ渡す依頼の具体文 |
| 記録項目の共通条件 | 修正方針 |
| 反復ごとの成功判定 | 意味や挙動が変わっていないかの確認条件 |
| 重複指摘のまとめ方 | 未使用の確認シナリオの要否 |
| 起動不能の扱い | 最終報告の必須項目 |
| 継続中と最終報告の分離 | 完了に必要な使用側の条件 |

## 用語と役割

| 用語 | 意味 |
|---|---|
| 実行担当者 | 対象、評価条件、修正、記録、停止判断を管理する |
| 評価者 | 対象を白紙で読み、または実行し、評価結果と迷った点を返す |
| 補助評価者 | 要約、一致判定、静的確認など、使用側の規則が明示する補助評価だけを行う |
| 利用者 | 改善結果を受け取る相手 |
| 対象 | 評価者に読ませる、または実行させるもの |
| 使用側 skill | 評価対象の種類ごとに、評価観点、判定項目、修正方針、停止条件、完了判定を定める skill |
| 評価の区切り | 評価者を分けて起動するまとまり。文章、観点、シナリオなど、使用側 skill が具体化する |
| 判定項目 | 評価の区切りごとに達成可否を判定する項目 |
| 指摘 | 評価者が報告した未達、不明瞭点、補った前提、詰まった箇所 |
| 重複指摘のまとまり | 同じ問題を別表現で重複計上しないための単位 |
| 独立評価 | 別に起動した評価者に対象を確認させ、その結果と迷った点に基づいて判定する評価 |

現在の実行担当者自身を評価者として扱わない。利用者から実行担当者が新規起動されていても、その実行担当者は今回の対象を評価する独立評価者ではない。

## 独立評価者の起動要件

`tuning` または `tuning` に従う使用側 skill を実行する場合、独立評価者の起動はその評価手順の実行要件として扱う。起動要件は、skill の選択経路や呼び出し経路で変えない。

独立評価者の起動可否は、明示的な起動禁止と起動手段の有無で判断する。個別の起動指示は必須条件にしない。

起動前には、追加評価者、委任、または並列作業が明示的に禁止されていないことと、新規評価者の起動手段が提供されていることを確認する。禁止が明示されていないだけの状態は、起動しない理由にしない。

## 評価条件を固定する

実行担当者は、利用者の指示または使用側 skill の規則から、対象、評価の区切り、判定項目、評価者へ渡す依頼、修正方針、停止条件、成果物範囲を評価前に固定する。

| 不足条件 | 扱い |
|---|---|
| 指示から一意に決まる条件がある | 評価前に今回の条件として固定する |
| 複数解釈があり、完了判定または成果物の意味が変わる条件がある | 評価前に確認する。確認できない場合は未確認事項に分ける |
| 指示範囲外の条件がある | 今回の対象外として記録する |

新規評価者を起動できない環境では、評価結果や改善案を作らない。起動できなかった理由と、実施しなかったことだけを記録する。

## 使用側の規則

使用側 skill がある場合、実行担当者は使用側の規則を正本として読む。共通ルールは評価者の起動、評価結果の整理、指摘の統合、修正、再評価、起動不能時の記録を担当する。

使用側の規則は、評価対象、評価の区切り、判定項目、評価者へ渡す依頼、指摘の扱い、修正範囲、完了判定、停止条件、出力規則を定める。これらが評価前に一意に決まらない場合は、評価を実施せず、不足している条件、評価を実施していない事実、作らなかった成果物を記録する。

## 反復の流れ

次の流れで扱う。

```
評価条件を固定する
    利用者の指示または使用側の規則から、対象、評価、指摘の扱い、修正範囲、完了判定、出力規則を固定する。
│
├ 独立評価者の起動可否を確認する
│   skill 実行に含まれる起動条件、明示的な起動禁止、起動手段の有無を確認する。
│   起動禁止または起動不能に当たる場合は、独立評価を実施せず、固定した出力規則で理由を記録して止める。
│
├ 評価対象を作る
│   対象の定義に従う。対象外条件に当たる場合は、固定した出力規則で停止する。
│
├ 評価者へ渡す
│   評価の区切りごとに、固定した依頼と共通条件を合わせた依頼を新しい評価者へ渡す。
│   同じ反復内でも評価の区切りごとに別の評価者を使う。
│   評価の区切り同士が読み取り専用で、同じ対象を直接変更しない場合は、同じ反復内で並列に評価者を起動してよい。
│
├ 評価結果を整理する
│   評価者の返却を、指摘あり、指摘なし、評価不能に分ける。
│
├ 指摘を統合する
│   同じ問題を重複計上しないよう、使用側の規則で指摘をまとめる。
│   並列評価の結果は、修正前に実行担当者が統合し、同じ問題を重複して扱わない。
│
├ 最小修正する
│   自動修正可能な未解決指摘だけを、修正範囲の中で最小修正する。
│
├ 再評価する
│   修正した場合は、新しい評価者で再評価する。前回の評価者を再利用しない。
│   並列評価の後に対象を変更した場合は、変更後の対象に対して、変更の影響を受ける評価の区切りを新しい評価者で再評価する。
│   影響範囲を一意に絞れない場合は、使用側 skill が必要とする評価の区切りをすべて再評価する。
│
├ 直接修正できない指摘を分ける
│   最小修正後も同じ問題が残る場合は、直接修正できない指摘として完了判定へ渡す。
│
└ 最終報告を組み立てる
    自動修正可能な未解決指摘をすべて処理した時点で、使用側の完了判定と出力規則に従う。
    並列評価の一部または全部が成功しても、使用側 skill の完了条件を満たすまでは全体完了として扱わない。
```

評価者の返却状態は次で扱う。

| 状態 | 必須情報 | 扱い |
|---|---|---|
| 指摘あり | 評価の区切り、指摘内容、根拠、修正案、評価者が迷った点 | 重複指摘をまとめ、判定規則を適用する |
| 指摘なし | 評価の区切り、確認範囲、評価者が迷った点 | 確認済みの範囲として記録する |
| 評価不能 | 理由、不足入力、確認できた範囲 | 指摘なしとは扱わず、完了判定で未評価または未収束の材料にする |

使用側の規則が検証コマンドまたは検証ルールを定めている場合、最終報告前に実行する。修正件数が 0 件でも、完了判定が検証を要求しているなら実行対象にする。検証失敗は未収束として扱う。検証が完了条件に含まれるのに、検証ルールが無い、特定できない、または実行不能な場合は、検証未完として理由を出力し、コード読解だけで検証済みと書かない。

## 評価者へ渡す依頼の共通条件

評価者へ渡す依頼には、固定した評価条件に加えて次を含める。

| 条件 | 内容 |
|---|---|
| 役割境界 | 評価者は渡された対象とシナリオの範囲だけを扱う |
| 追加起動の禁止 | シナリオが明示しない限り、評価者はさらに別の評価者を起動しない |
| 成果物範囲 | 成果物、判定、迷った点のどこまで返すかを明示する |
| 判定項目 | `[critical]` など、使用側 skill が定める必須項目を評価前に固定する |
| 不明瞭点 | 実際に詰まった箇所、解釈に迷った文言、補った前提を報告させる |
| 再試行 | 同じ判断をやり直した回数と理由を報告させる |

評価者の成果物に、実行担当者の反復計画、差分適用、完了判定を含めるのは、シナリオがそれを成果物として明示した場合だけにする。

## 記録と判定

| 項目 | 共通扱い |
|---|---|
| 反復判定 | 今回のテーマまたはシナリオで固定した `[critical]` 項目が全て達成されたときだけ成功とする |
| 評価結果 | 評価者の返却状態、指摘、確認範囲、評価不能の理由を記録する |
| 使用側の評価軸 | 使用側 skill が定める場合だけ記録する |
| 再試行回数 | 評価者の報告から抽出し、実行担当者が推測しない |

反復判定は今回の最低ラインとして扱う。全体の完了は、使用側 skill が定める全体判定条件を満たした時点で判断する。一部の観点やシナリオが成功した段階では、継続中の報告にする。

## 重複指摘のまとめ方

同じ評価の区切りで、同じ判定項目が、同じ問題箇所と同じ理由により落ちている場合は同じ問題として扱う。評価者ごとに表現が違っていても、実行担当者はレポート本文を読み、同じ問題を別件として数えない。

使用側 skill がより具体的な重複判定の定義を持つ場合は、その定義を優先する。

## 起動不能

新規評価者を起動できない環境では、独立評価を実施しない。

| 状況 | 扱い |
|---|---|
| 追加評価者、委任、または並列作業が明示的に禁止されている | 起動せず、独立評価未実施として扱う |
| 明示的な起動禁止がない | 起動禁止または起動不能の理由にしない |
| 起動手段が提供されていない | 起動不能として扱う |
| 起動手段が無効化されている | 起動不能として扱う |
| 認証失敗、権限不足、接続失敗、接続先エラーで起動が成立しない | 起動不能として扱う |
| 現在の実行担当者を評価者に見立てる案が出た | 代替しない |

起動しない場合または起動不能時は、評価結果や改善案を作ったように書かない。理由と実施しなかったことを記録する。使用側 skill が報告欄を指定している場合も、未生成の欄には未生成の理由を書く。

## 継続中と最終報告

| 状態 | 扱い |
|---|---|
| 完了条件に達していないが評価を続けられる | 最終報告にせず、継続中として扱う |
| 途中経過を利用者へ伝える必要がある | 中間更新として、残項目と次に回す評価だけを短く伝える |
| 反復判定だけが成功した | 全体の完了として扱わない |
| 停止理由に達した | 使用側 skill の完了判定条件で最終報告を組み立てる |

最終報告として返せる状態、全体判定の値、残項目、未評価項目、未達項目、使用側の評価軸の扱いは使用側 skill の完了判定を正本にする。使用側 skill が完了判定の規則を持つ場合は、停止理由を決めた後にその規則を読む。

## 禁止する省略

| 省略 | 扱い |
|---|---|
| 自分で読み直せば十分 | 独立した評価者を起動する |
| 1 回成功したので完了 | 連続確認や全体判定条件を満たすまで完了にしない |
| 同じ評価者を使い回す | 再利用しない |
| 使用側の評価軸だけで判断する | 評価者が迷った点や補った前提を主に扱う |
| シナリオに合わせて対象を寄せる | 具体例を本文へ移植せず、抽象ルールへ戻す |
| 起動不能時に静的レビューへ切り替える | 使用側 skill が明示した補助モード以外では代替しない |
