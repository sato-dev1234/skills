# 原文をツリーにして文章を書く

原文の全主張を一本のツリーに整理し、その関係から文章を書く。

## 対象と進め方

- 新しく書く場合は、確認した根拠から下書きを作って原文とする。
- 工程を指定されたら、その範囲だけ進める。
- 既存成果物が依頼を反映していなければ、該当する工程から進める。
- レビューだけの依頼では対象ファイルを編集しない。

## 原文からツリーへ

1. 読み手、目的、依頼範囲と根拠を確かめる。指定されたファイル、差分、コミット、PRなどを調べ、取得できない情報を推測で埋めない。
2. 対象となる原文の全文を確定する。読み手が理解するために必要な具体的知識とその根拠位置を決める。各主張は、主体、対象、動作や状態、条件、理由、原文位置を、比較に必要なところまで分ける。
3. [文章の規則](references/writing.md)で、原文の主張を一本の仮ツリーに置く。話題名だけの一覧をツリーと扱わない。
4. 同じ親の子を、共通する主体・対象・動作や状態・場面でまとめる。できた親の直下でも共通要素を探す。同じ事柄について条件や対象別の結果を言い分ける子は「対応」に、同じ条件で並ぶ独立した指示や結果は「列挙」に、原文に実行順序の根拠がある子は「手順」に整理する。別の扱いを指示する子は別枝に置く。親の名前だけでまとめて終わらない。
5. 整理した親子の関係を原文に戻して確かめる。並列する指示、順序、理由の関係も保つ。一つの動作に付く複数の内容は分割しない。
6. 全主張がツリーの項目、理由、保持、重複の統合、または未解決のいずれかに対応することを確かめる。

## ツリーから文章へ

点検後のツリーを、枝ごとに次の形へ写す。

対応の枝は、親の共通部分を表の見出しにする。条件が異なる場合は条件を行にする。条件が共通する場合は比較対象を行にし、対応する結果を列にする。軸を同順位で決められなければ未解決にする。

| ツリーの枝 | 文章の形 |
|---|---|
| 節 | 見出し |
| 対応 | 条件または比較対象ごとの結果を比較できる表 |
| 列挙 | 共通部分の導入と箇条書き |
| 手順 | 番号付きリスト |
| 単独の項目 | 段落 |
| 図の接続・保持 | 図、引用、コードなど元の形 |

原文の言葉を残す箇所も、配置はツリーに従う。ツリーで対応にした枝が完成文でも比較できることを確かめ、表・箇条書き・段落への写し方が違えば直す。

### 原文と完成文を照合する

原文位置から完成文の行・項目・段落まで辿って照合する。複数の内容が一つの動作に付く場合は、その動作を分割しない。原文にない条件や主体を足さず、確定できないことは未解決にする。

## 依頼別の提示

### 文章レビューとツリーの提示

文章レビューでは、話題ごとに原文・ツリー・書き直した文章を対応させる。構造を直す箇所は、レビューでも書き直した完成文を示す。

ツリーの提示を求められた場合は、その範囲で示す。

### コミットメッセージとPRコメント

コミット、コミットメッセージ作成、git commitの依頼では、起草時と採用判断時に[コミットメッセージの規則](references/commit-message-rules.md)を読む。PRコメントの文章には[PRコメントの表現](references/pr-comment-rules.md)も読む。

## 完成時

完成時は文章と重要な未確認事項を返す。コミットメッセージが完成し、利用者がコミットを明示していないときは、完成報告を添えず、メッセージだけ返す。
