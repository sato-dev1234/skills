# コミットメッセージの規則

コミット前にステージ済み差分を読み、履歴だけを読む人が変更の成果と意図を把握できる文にする。コミット対象の採否や技術的正しさは、このスキルでは決めない。

## 差分からメッセージを作る

1. ステージ対象の差分と、必要なら直近の履歴を確認する。
2. 差分に基づく下書きを原文として用意する。
3. [文章作成ガイド](../SKILL.md#文章を作成する)の工程でツリーを作る。
4. ツリーからメッセージを書く。

対象の差分を確認できない場合は、次のように対応する。

- 不足している情報を示す。
- メッセージの確定へ進まない。

## ツリーから件名を書く

件名は、ツリーに記録した差分全体に共通する変更の意図を、既定では1文で表す。

件名では、次の出力は行わない。

- ツリーの対応や列挙を表や箇条書きへ展開する。
- 節ごとの見出しを付ける。

主張の分解、関係と言葉の確定、原文・ツリー・文章の照合は省略しない。

## メッセージを書く

- 既定は日本語の1文とし、60字前後を目安にする。利用者の言語指定またはリポジトリの明示規則があれば従う。
- `fix:`などの慣習的な接頭辞は使える。既存履歴が英語という理由だけで件名全体を英語にしない。
- ファイルや識別子の列挙ではなく、何がどう変わり、なぜ必要かを成果として書く。
- 依頼文や作業メモをそのまま転記しない。
- 件名だけでは足りない場合に本文を加え、差分の細部や件名の繰り返しを書かない。
- 確認していない動作、テスト、仕様を完了した事実として書かない。
- 共同作成者行を付けない。

## メッセージを採用する条件

次の条件をすべて満たす場合だけメッセージを採用する。満たさない場合は書き直す。

- 件名が、ステージ済み差分全体に共通する変更の意図を表している。
- 固有名詞は必要なものだけを使い、何がどう変わるかを併せて示している。
- 本文に不要な情報がない。
- 共同作成者行がない。

## コミットする

利用者がコミットを明示している場合は、次の順に進める。

1. ステージ済みの差分を読む。
2. 「メッセージを採用する条件」をすべて満たし、共同作成者行がないことを確認する。
3. コミットする。

コミットの実行、ステージング、push の要否は利用者の指示に従う。メッセージが完成し、利用者がコミットを明示していないときは、メッセージだけ返す。
