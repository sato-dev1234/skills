# 原文からツリーを作り、文章へ写す

文章を作成する前に、原文の主張を一本のツリーへ書く。

## ツリーを作る

### 読み手の前提を決める

読み手の前提は、理解に必要な具体的知識と原文・依頼の根拠位置で決める。難しい語があるだけで必要な専門性を上げない。

### 主張を分けて置く

原文の段落や表の形で枝を決めない。本文段落の各文も分解する。

| 枝 | 記録すること |
|---|---|
| 節 | 原文全体と第1階層の話題 |
| 項目 | 主体、対象、動作または状態、内容、時点、条件、原文位置 |
| まとまり | 共通の主体、場面、条件と、それが掛かる項目 |
| 対応 | 条件や対象が異なるときの、同じ事柄に対する結果 |
| 列挙 | 同じ条件で並ぶ独立した結果や指示 |
| 手順 | 原文に根拠のある実行順序 |
| 理由・未解決 | 理由が掛かる項目、根拠なしには決められない箇所 |

複数の内容が一回の動作に属する場合は一項目にする。対象ごとに条件や結果が変わる場合は分ける。離れた主張を統合するのは、主体、対象、動作・状態、内容、条件、場面が一致するときだけとし、統合前の原文位置を両方残す。

主語の省略や食い違いは、原文または確認済みの根拠で解ける場合だけ確定する。足りない根拠や矛盾を、自然な文章に見せるために補わない。

### 条件と適用範囲を保つ

条件の組合せは「すべて成立」「いずれか成立」「成立しない」を区別する。子の条件は親の条件とともに成立する。「場合も」「にかかわらず」を「場合だけ」へ変えない。条件、理由、否定、数量、時点、説明か指示かの範囲を保つ。

同時に成立する条件はそれぞれ適用し、矛盾する扱いだけを未解決にする。原文にない優先順位や「それ以外」を足さない。「記載なし」を「表示しない」に変えない。

## 共通要素で親と子を整理する

同じ話題の主張から共通する主体・対象・動作や状態・場面を見つけ、親にまとめる。できた親の直下でも共通要素を探し、同じ事柄について条件や対象別の結果を言い分ける場合は対応、同じ条件で並ぶ独立した指示や結果は列挙、原文に実行順序の根拠がある場合は手順として表す。別の扱いは別枝に置き、各主張の条件と適用範囲を保つ。

手順は原文に順序の根拠がある場合だけにし、その順序が前提とする依存関係を保つ。

### 注文キャンセルの例

例えば「出荷前の注文はキャンセルできる。出荷済みの注文はできない。受け付けなかった注文は変更しない」は、次のように整理して書く。

```text
注文のキャンセル
├─ 注文の状態 → キャンセル可否
│  ├─ 出荷前 → できる
│  └─ 出荷済み → できない
└─ 受け付けなかった注文の扱い → 変更しない
```

| 注文の状態 | キャンセル可否 |
|---|---|
| 出荷前 | できる |
| 出荷済み | できない |

受け付けなかった注文は変更しない。

## ツリーから文章へ写す

### 対応表の軸を決める

対応表は、条件が異なるなら条件を行にする。条件が共通なら比較対象を行にし、対応する結果を列にする。軸を同順位で決められなければ未解決にする。表や箇条書きの共通条件は、適用先が分かる位置に置く。

### 原文と完成文を照合する

原文位置→ツリーの枝→完成文の位置を全主張について辿り、関係と適用範囲が変わっていないか確認する。読み手の前提に合わせて言葉を選び、書けない条件は未解決として示す。レビューでは修正不要の話題も判定結果を残す。
