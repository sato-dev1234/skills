# 原文からツリーを作り、文章を書く

原文の主張と関係を1本のツリーへ整理し、そのツリーから文章を書く。新しく書く場合は、確認した根拠から下書きを作り、原文として扱う。読み手、目的、構成は最初に決め、項目ごとに選び直さない。

具体的な適用は、[原文からツリーを作る例](../examples/reconstruction.md)と[ツリーから文章を書く例](../examples/composition.md)にある。ツリーだけを求められた場合は「照合」まで行う。

## ツリーを作る

### 読み手の前提を記録する

原文全体の主題、説明内容、読み手に求める行動から、扱う分野と理解に必要な知識を読み取る。読み手や目的に利用者の指定があれば優先する。

表題の直下に「読み手の前提」を置き、次の内容を記録する。

| 欄 | 記録する内容 |
|---|---|
| 扱う分野 | 文章が説明する分野 |
| 必要な知識 | 「見出しと段落の違いが分かる」のような具体的な知識。「専門家向け」などの段階名だけにしない |
| 根拠 | 原文や依頼の位置と、そこから分かる目的・行動 |

前提を決める際は、次を守る。

- 難しい単語があることだけで、必要な知識を増やさない。普通の説明に置き換えても文章の目的が変わらなければ、単語自体は専門性の根拠にならない。
- 前提は文書全体で共有する。特定の節だけ別の知識が必要なら、説明内容の根拠とともにその節へ記録する。
- 専門用語を残すために前提を変更しない。

### 主張を分解する

#### 記録する要素

独立した主張を1項目とし、次の要素へ分ける。原文にない要素を推測で補わず、不要な欄は作らない。

| 要素 | 記録するもの | 分解の扱い |
|---|---|---|
| 主体 | 動作や判断を行うもの | 文法上の主語と同一とは限らない。受身でも行う側が原文から分かれば記録する |
| 対象 | 動作が向かうもの、または状態を述べるもの | 「ボタンが非表示である」なら対象はボタン、状態は非表示。画面という主体を推測で足さない |
| 動作 | 表示する、変更する、受け付けないなど | 否定、可能、義務、推量を含む意味を保つ。「表示しない」と「表示できない」を同じにしない |
| 状態 | 非表示、キャンセル済み、変更されないなど | 状態を述べる主張に使う。動作と状態を両方無理に埋めない |
| 内容・値 | 表示する文章、設定する日数、判定に使う設定など | 単なる文字列の列挙にせず、「案内の内容」「設定日数」「判定に使う設定」のように役割を付ける |
| 条件 | 主張が成立する場合 | 「判定対象：注文／判定：期限を過ぎている」のように、何について何が成立するかを分ける |
| 場面 | 場所、処理の時点、操作中の状況 | 「場所：注文詳細画面」「時点：キャンセル要求の受付時」のように役割を付ける |
| 理由 | 主張が成立する理由 | 理由も項目として分解し、理由が掛かる項目またはまとまりへ付ける |

項目は説明と指示に分ける。主体が利用者でも、操作を説明しているだけなら指示に変えない。主体欄には行う側、対象欄には動作や状態の対象を置き、名前の種類で出力形式を決めない。

#### 分解を止める位置

条件、対象、動作・状態、値を、項目間で比較できるところまで分ける。

| 内容の形 | 分け方 |
|---|---|
| 固有名、引用、通常の名称 | 意味の単位を保つ。「キャンセルボタン」を単語ごとに分けない |
| 条件が対象の説明に含まれる | 条件と対象を分ける。「期限を過ぎた注文のキャンセルボタン」なら、注文の条件と表示対象に分ける |
| 時点と回数が動作に付く | 時点は場面、回数は値にする。「サインイン直後に1度だけ取得する」なら、取得時点と回数を別に記録する |
| 値の役割が明らか | 「回数：1度だけ」「変更の有無：これまでどおり」のように記録する |
| 送信先や移動先など、基本欄だけでは意味が足りない | 役割を付けた内容・値として残し、対象へ無理にまとめない |
| 1回の動作が複数の対象を一体として扱う | 1項目に保つ |
| 対象ごとに結果や条件が異なる | 項目を分ける |

条件や修飾を分ける際は、次を守る。

- 数量、時点、否定、限定が何に掛かるかを保つ。否定の範囲が曖昧なら解釈を固定しない。
- 「場合も」「にかかわらず」を、「場合だけ」の条件へ変えない。
- 複数の判断は「すべて成立」「いずれか成立」「成立しない」で組み合わせる。入れ子は両方が成立する条件なので、「または」を入れ子にしない。
- 独立した主張や分類に使う条件を、自由文の補足へ埋め込まない。

表現が違っても、原文から確認できる同じ意味の要素は同じ欄に置く。ただし「画面が表示しない」と「ボタンが非表示である」は、行う側と状態の記述範囲が異なる。表示結果として比較できても、欠けた主体や因果を補って同一の主張にはしない。

#### 原文との対応

原文の位置は、次のように残す。

| 場面 | 記録する位置 |
|---|---|
| 項目や関係を取り出す | 元になった原文の位置 |
| 1文を複数項目に分ける | 各項目に同じ位置 |
| 別の箇所から主体や条件を補う | 補った根拠の位置も追加 |
| 重複する主張をまとめる | 統合前の両方の位置 |

主語が省略されていても、参照先が確定する場合はツリーに記録する。重複は、主体、対象、動作・状態、値、条件、場面、説明か指示かが一致する場合だけ統合する。過去の動作と現在の仕様、未設定と設定済みの条件を混ぜない。

## 共通部分と関係を組み立てる

### 記法と適用範囲

| 記法 | 役割と書き方 |
|---|---|
| 節 | 話題を表す |
| まとまり | 共通情報の適用範囲。「共通」と、その情報が掛かる項目・関係を分けて置く |
| 項目（説明）、項目（指示） | 分解した主張を記録する |
| 理由 | 理由となる項目を子に置く |
| 手順 | 項目や関係を実行順に置く |
| 図の接続 | 始点、終点、接続の意味を記録する |
| 保持 | 内容、または内容を取得できる固定版の所在を記録する |

```text
まとまり
├─ 共通
│  ├─ 主体：サーバー
│  └─ 条件
│     ├─ 判定対象：キャンセル要求
│     └─ 判定：受け付けられなかった
└─ 列挙
   ├─ 項目（説明）
   │  ├─ 対象：注文
   │  └─ 動作：変更しない
   └─ 項目（説明）
      ├─ 対象：操作履歴
      └─ 動作：記録しない
```

共通情報は、次の範囲で扱う。

- まとまりの内容すべてに適用する。前に書かれた別の項目からは引き継がない。
- 同じ話題の連続した項目で共有する。原文に明示された表・列挙の整理を除き、離れた項目を集めるために並べ替えない。
- 途中で主体や条件が変わる場合は、共通情報を上書きせず、まとまりを分ける。
- 子に条件を追加した場合は、共通条件と両方が成立するものとして扱う。
- 理由は、原文で全項目に掛かっている場合だけまとまりへ付ける。

共通の条件・場面はまとまりに、個別の条件・場面は項目内に置く。適用先が1項目でも複数でも、同じ細かさで分解する。

### 話題と順序

| 決めるもの | 基準 |
|---|---|
| 第1階層の節 | 依頼で指定された構成の、話題を分ける単位に従う。指定がなければ原文の話題で分ける。見出しもなければ、対象や操作場面の切り替わりで分ける |
| 話題の順序 | 構成の指定を優先し、指定がなければ初出順にする |
| 各話題の項目の順序 | 初出順にする |
| 複数の話題に掛かる主張 | それらを含む最も近い共通の節に置く |

関連するという理由だけで話題を広げない。並べ替えは、理由の所属、重複の統合、原文で明示された対応・手順に必要な範囲に限る。

### 関係を決める順序

話題の構成を決めた後、各話題で次の順に進める。判断の根拠には、分解した要素と原文位置を使う。

1. コード、引用など書き換えない内容を「保持」にする。
2. 各項目の条件・場面・理由の適用先を決める。
3. 構成や依頼で必要な図の接続を記録し、同じ内容を本文へ重複出力しない。
4. 実行の前後関係や試行順序が要求されている項目を「手順」にする。
5. 手順の外と各手順の内部で、共通部分をまとめ、以下の基準で「対応」「列挙」「通常の説明」に分ける。
6. 読み手の前提に照らして呼び方と見出しを確定し、原文の主張と照合する。

### 対応・列挙・通常の説明の区別

| 分解した内容の関係 | 記録する関係 | 出力 |
|---|---|---|
| 条件や対象の違いごとに、同じ問いの答えが並ぶ | 対応 | 表 |
| 共通の条件・場面で起こる複数の結果、または同じ対象への複数の並列した動作がある | 列挙 | 共通部分の導入と箇条書き |
| 複数の独立した指示があり、実行順序はない | 列挙 | 箇条書き |
| 上記の対応・並列関係がなく、説明が続く | 通常の説明 | 段落 |

対応が成立する場合は列挙より優先する。原文の表や対象別の属性を使い、明示がなくても条件・対象・結果に同じ問いを適用できれば対応を取り出す。主体が一致するだけでは対応にも列挙にもしない。

#### 対応の行と列

| 決めるもの | 基準 |
|---|---|
| 行と列の根拠 | 利用者の指定、構成の固定欄、原文の表を優先する |
| 上記の指定がない場合の行 | 条件で結果が変わるなら条件、条件が共通なら比較する対象にする |
| 複数条件で決まる1件 | 条件を組にして残す |
| 列 | 各行に対する同じ問いを使う。同じ場面・動作の対象別に結果があれば、対象別の列にできる |
| 同じ優先度の分け方が複数あり、根拠が定まらない | 自由に軸を選ばず、未解決にする |

表示を説明する場合、「ボタンをどう表示するか」「案内をどう表示するか」が条件ごとの問いになる。対象が異なるという理由だけでは列を増やさない。

完成した対応には、次を記録する。

- 行の見出し、列の見出し、各行と値、原文位置。
- 各項目に適用する行の条件や対象。
- 各項目が答える列。値の記載がなければ、その列に「記載なし」を置く。

文章化では行や列を作り直さない。

#### 列挙と単独の主張

列挙は2項目以上とし、各項目が共通部分に対する独立した答えになることを確かめる。

- 理由、言い換え、時間順の経過は、並んでいるだけでは列挙にしない。
- 「受付を拒否したときに行わないこと」に注文の変更と操作履歴への記録が並ぶ場合は、列挙にする。「結果」という1列の表にはしない。
- 1つの対象への1つの動作に複数の要素があるだけでは、表や列挙にしない。
- 原文で明示された1行の表は保持できるが、単独の主張を分解しただけで1行の表にはしない。

### 条件が重なる場合と欠けている情報

| 状況 | 扱い |
|---|---|
| 複数の行の条件が同時に成立する | 原文が別の扱いを定めていなければ、それぞれの主張を適用する |
| 同時に適用すると結果が矛盾する | 未解決にする |
| 表の組み合わせに原文の記載がない | 「記載なし」とする |

条件には、原文にない優先順位や「それ以外」を追加しない。全組み合わせを勝手に生成せず、「記載なし」を「表示しない」「対象外」「未確認」に読み替えない。

### 言葉を決める

主張と関係を組み立てた後、文章化の前に言葉を確定する。各要素、表題、節名、列名、図の説明を対象に、読み手の前提と使われる意味を照らす。

| 確認すること | 判断と修正 |
|---|---|
| この項目で何を指すか | 対象、動作、位置、性質などを具体的に言い表す。特定できなければ原文を確認する |
| その意味で理解するために必要な知識は何か | 文書または節の前提と照らし、別分野の専門的な意味を持ち込んでいないか確かめる |
| 専門的な区別が主張や行動の理解に必要か | 普通の言い方で区別を保てるなら置き換える。定義が正しいことや原文にあることだけでは残さない |
| 前提の範囲内でも省略されすぎていないか | 短い呼び方が何を指すか伝わりにくければ、対象や動作を具体的に書く |
| 前提にない専門概念そのものを説明する必要があるか | 意味を失う言い換えはせず、必要な説明を同じツリーに含める。原文や確認済みの根拠で説明できなければ不足として扱う |

言葉を揃える際は、次を守る。

- 同じ対象には同じ呼び方を使い、「期間」と「期限」のように意味が違うものは統合しない。
- 正式名や初出の表記は指すものの確認に使い、そのまま採用する理由にはしない。見出しや列名も同じ基準で確定する。
- 指定された文字列、製品名、画面の表示名、コードの識別子など、照合に必要な名称は保持する。専門分野に正式な名称があるという理由だけでは保持しない。
- コードと引用原文は書き換えず、必要な説明は周囲に置く。その説明には通常の判断を適用する。
- 単語の禁止一覧や文字数だけでは判定しない。

修正は同じツリーに反映する。別の単語表や修正用ツリーを文章化の必須入力にはせず、レビューで必要な場合だけ修正前後と理由を示す。

## ツリーから文章を書く

### 出力単位と共通部分

コミットメッセージの件名には、[コミットメッセージの規則](commit-message-rules.md#ツリーから件名を書く)を適用する。本文を加える場合は、以下の出力規則に従う。

| ツリーの内容 | 出力 |
|---|---|
| 節 | 見出し。最上位は表題 |
| 対応 | ツリーに記録した行・列の表 |
| 列挙 | 箇条書き。説明と指示の両方を扱う |
| 手順 | 番号付きリスト |
| 通常の説明 | 連続する項目を段落にする |
| 単独の指示 | 1文の段落 |
| 図の接続 | 図 |
| 保持 | 引用・コードなど元の形式 |
| 読み手の前提、原文位置、分類の根拠 | 通常の本文には出さない |

| 情報の適用範囲 | 書く場所・省略の扱い |
|---|---|
| 表や箇条書きに共通する主体・条件・場面 | 直前の導入文に置く |
| 行の条件や列の対象で分かる情報 | セル内では繰り返さない |
| 個別項目だけの条件や理由 | その項目の中に残す |
| 個別項目で主体が異なる | その主体を書く |
| 段落内で主体を共有する | 最初の文で示し、同じまとまりの後続文では省略できる |
| 別の主体が現れ、参照先が曖昧になる | 主体を明示する |

省略する主体もツリーには残す。1項目は意味を照合する単位であり、出力する文の数とは限らない。

- 表のセルや箇条書きは、共有要素を除いた句で書ける。
- 通常の段落は原則として1項目を1文にし、文章化で任意に主張を合併しない。並列関係はツリーで確定する。
- 通常の説明は、節・まとまり・対応・列挙・手順・図・保持、または指示への切り替わりで区切る。
- 要素を分けた数を、文や箇条書きの数にしない。

### 意味を保持する

文章化では、次を守る。

- 動作・状態、内容・値、数量、否定、条件とその組み合わせ、説明か指示かを保つ。
- 共通部分を各項目へ戻して読んでも、元の主張と同じ意味になるようにする。
- 新しい条件、主体、因果関係、専門用語を追加しない。
- コードと引用を書き換えない。

| 内容 | 配置と確認 |
|---|---|
| 個別項目の理由 | 対象と同じセル・箇条・番号・段落に置く |
| まとまり全体の理由 | まとまりの直後に置く |
| 離れた複数項目への理由 | 原文位置で適用先を記録し、文章でも対象を明示する |
| 手順 | 原文の「先に」「その後」「失敗したら次を試す」などを根拠にする。依存を守り、同等なら初出順にする。掲載順だけでは手順にせず、循環は未解決にする |
| 手順内の表・箇条書き | 同じ規則を適用する |
| 図 | ツリーの項目、接続方向、条件、理由を写す。原文にない接続は補わず、不足として扱う |
| 表題・節名 | ツリーで確定した名前を使う |
| 最上位の下に節が1つだけあり、読み手の前提以外の内容がない | 条件や場面が節名だけに残っていないことを確かめ、重複する節の見出しを省略できる |

## 照合

文章化する前に、ツリーを確認する。

- 原文の全主張に、項目・理由・保持・重複としてまとめた項目のいずれかが対応している。
- 要素、順序、条件と理由の所属が保たれ、共通情報を各項目へ戻しても意味が変わらない。
- 分類に必要な条件や対象が、動作欄の文章に埋まっていない。
- 読み手の前提に照らして言葉が確定し、残した専門用語の必要性を項目の内容から説明できる。

文章化した後は、原文・ツリーと照らし、表の行と列、箇条書き、段落、主体、条件、理由、数量、否定、指示、引用の抜けや意味の変更を直す。本文だけを直してツリーとの不一致を残さない。

| 判断できない内容 | 扱い |
|---|---|
| 関係のない説明 | 通常の項目として扱う。未解決にはしない |
| 明示された関係や条件の適用先 | 箇所と不足を記録して原文・依頼を再確認し、情報が足りない場合だけ利用者へ確認する |
| 規則の競合 | 自由に形式を選んで埋めず、修正事項として扱う |

レビューでは、次を示す。

- 話題ごとの原文・ツリー・書き直した文章の対応。
- 必要な言葉の修正前後と理由。毎回2本のツリーや全単語の一覧は要求しない。

対象の原文へ修正を反映するのは、利用者が依頼した場合だけである。
